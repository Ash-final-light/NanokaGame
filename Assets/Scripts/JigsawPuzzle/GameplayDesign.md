# 拼图玩法说明

## 1. 文档目的

本文档定义 `Jigsaw` 场景第一版拼图玩法，作为后续脚本、场景和测试实现的依据。

本阶段只确定玩法与实现边界，不创建脚本，不修改场景对象，不调整图片导入设置。

## 2. 当前资源与场景基线

### 2.1 场景

目标场景：

```text
Assets/Scenes/Jigsaw.unity
```

当前已存在的主要对象：

```text
Jigsaw
├── Main Camera
├── BG
├── Klotski_BG
│   ├── Btn_Exit
│   ├── Btn_Restart
│   └── Root_Complete
│       ├── TMP_CompleteTitle
│       ├── TMP_CompleteTime
│       ├── TMP_CompleteStep
│       ├── Btn_CompleteRestart
│       └── Btn_CompleteTitle
└── nanoka_image1
```

说明：

- `Klotski_BG` 是沿用华容道命名的 UI 根对象，后续实现拼图时应改为表达拼图用途的名称，但本阶段不重命名。
- `Root_Complete` 当前默认隐藏，可以继续作为拼图完成面板的基础。
- 场景中尚未看到难度选择面板、拼图棋盘根对象、拼图块容器和独立的游戏中计时/步数文本。
- 后续实现交互前必须确认场景中存在且只存在一个可用的 `EventSystem`。

### 2.2 原图

原图资源：

```text
Assets/Arts/Images/nanoka_image1.png
```

当前资源信息：

| 项目 | 当前值 |
| --- | --- |
| 尺寸 | `4096 × 1816` |
| 宽高比 | 约 `2.256 : 1` |
| Unity 类型 | `Sprite (2D and UI)` |
| Sprite Mode | `Single` |
| Pixels Per Unit | `100` |
| Read/Write | 关闭 |
| Mipmap | 关闭 |
| Wrap Mode | Clamp |

`nanoka_image1` 当前是场景根对象，使用 `SpriteRenderer` 显示完整原图。后续开始游戏后，完整原图应隐藏或切换为低透明度参考图，正式可操作内容由运行时生成的拼图块显示。

当前对象的 X、Y 缩放比例不同，会改变原图宽高比。正式棋盘应使用固定棋盘区域并保持原图宽高比，不应继续依赖非等比缩放后的尺寸作为切分依据。

## 3. 第一版核心玩法

第一版采用“矩形网格切分 + 任意两块交换”的拼图规则。

基本规则：

1. 玩家进入 `Jigsaw` 场景后先选择切分程度。
2. 游戏根据选择的行数和列数，将 `nanoka_image1` 在运行时切成若干矩形拼图块。
3. 所有拼图块在棋盘格中随机打乱。
4. 玩家拖动一块拼图到另一块拼图所在的格子。
5. 松开指针后，两块拼图交换位置。
6. 当每块拼图都回到自己的目标格子时，游戏完成。

首版不采用以下规则：

- 不设置空白格，因此不是数字华容道式滑块拼图。
- 不允许拼图块自由散落、旋转或任意重叠。
- 不使用不规则拼图齿形。
- 不要求将拼图块逐块吸附到无界画布。
- 不在运行时生成新的 PNG、Sprite 资源文件或修改原图导入配置。

选择交换式玩法的原因是规则明确、输入稳定、移动端与鼠标均容易操作，也能避免自由拖放产生遮挡、层级、精确吸附和边界管理问题。

## 4. 难度与切分程度

第一版提供三档固定难度：

| 难度 | 列数 | 行数 | 拼图块数量 | 适用说明 |
| --- | ---: | ---: | ---: | --- |
| 简单 | 4 | 2 | 8 | 熟悉操作，快速完成 |
| 普通 | 6 | 3 | 18 | 默认难度 |
| 困难 | 8 | 4 | 32 | 需要更多观察与交换 |

三档难度都采用接近 `2 : 1` 的列行比，适合当前横向原图，使单块拼图接近方形，避免出现过度狭长的拼图块。

难度选择要求：

- 初次进入场景时显示难度选择面板，棋盘暂不接收输入，计时尚未开始。
- 默认高亮“普通”，但必须由玩家确认后才开始本局。
- 选择难度后生成对应数量的拼图块，再执行打乱。
- 本局进行中不允许直接改变切分程度。
- 如需改变难度，玩家应先返回难度选择界面并确认重新开始。
- `Btn_Restart` 只重开当前难度，不自动返回难度选择界面。

后续可以将行列数改为配置数据，但第一版不提供任意数字输入，避免极端数量造成性能和可用性问题。

## 5. 游戏流程

### 5.1 进入场景

进入场景后的初始状态：

- 显示背景、退出按钮和难度选择面板。
- 隐藏完成面板。
- 隐藏或禁用重开按钮，直到本局正式开始。
- 完整原图可以在难度选择面板中作为预览显示。
- 不生成拼图块，不开始计时，不记录步数。

### 5.2 开始一局

玩家确认难度后按以下顺序开始：

1. 锁定输入。
2. 清理上一局运行时生成的拼图块。
3. 根据选择的列数与行数切分原图。
4. 为每块拼图记录唯一编号和正确格子编号。
5. 将拼图块放入初始正确格子，确保布局尺寸准确。
6. 生成随机排列，并确保结果不是已完成状态。
7. 将拼图块移动到打乱后的格子。
8. 步数归零。
9. 计时归零并开始。
10. 显示游戏 HUD 和重开按钮。
11. 解锁输入，进入游戏状态。

如后续增加开场打乱动画，计时应在动画结束且玩家获得控制权时开始。

### 5.3 游戏中

- 玩家一次只能操作一个拼图块。
- 拖动开始后，被拖动拼图块显示在其他拼图块上方。
- 拖动过程中原格子保留占位提示，避免玩家误判来源。
- 松开到另一个有效拼图块或有效格子上时，执行交换。
- 松开到棋盘外、UI 上或无效区域时，原拼图块返回原位，不计步数。
- 交换动画期间锁定新的拼图输入。
- 一次有效交换计为一步。
- 交换结束后进行完成判定。

### 5.4 完成

当所有格子的当前拼图编号都与目标编号一致时：

1. 立即停止计时。
2. 锁定拼图输入。
3. 将所有拼图块对齐到精确目标位置。
4. 可淡出拼图缝隙或短暂显示完整原图，强调完成效果。
5. 显示 `Root_Complete`。
6. 在 `TMP_CompleteTime` 显示完成时间。
7. 在 `TMP_CompleteStep` 显示交换步数。

完成面板按钮：

| 按钮 | 行为 |
| --- | --- |
| `Btn_CompleteRestart` | 使用当前难度重新切分并打乱，开始新一局 |
| `Btn_CompleteTitle` | 返回标题场景 |

## 6. 运行时切图规则

### 6.1 切图方式

第一版使用同一张 `Texture2D` 在内存中创建多个运行时 `Sprite`，每个 Sprite 只引用原图的一个矩形区域。

该方案不需要：

- 开启原图 Read/Write；
- 读取或复制每个像素；
- 在项目中生成切片后的图片文件；
- 将原图改成 Multiple Sprite；
- 在 Editor 中提前为每档难度制作 Sprite Sheet。

运行时生成的 Sprite 和拼图对象只属于当前游戏会话，重开或离开场景时必须释放对应引用和对象。

### 6.2 切分边界

由于 `4096 × 1816` 不一定能被所有行列数整除，不能只使用整数除法计算固定块尺寸，否则可能丢失最右侧或最上侧像素。

每块边界应按整张图的比例独立计算：

```text
left   = Round(column       × textureWidth  / columns)
right  = Round((column + 1) × textureWidth  / columns)
bottom = Round(row          × textureHeight / rows)
top    = Round((row + 1)    × textureHeight / rows)
```

当前块的像素矩形为：

```text
x      = left
y      = bottom
width  = right - left
height = top - bottom
```

这样可以保证：

- 第一块从原图边缘开始；
- 最后一块精确到达原图另一侧边缘；
- 相邻块共享同一条边界；
- 不会因为余数而漏掉整列或整行像素；
- 不同块最多只有一个像素的尺寸差异。

### 6.3 坐标方向

Unity Sprite 的纹理矩形以左下角为原点，而棋盘格通常按左上角为第一个格子。

后续实现必须明确转换：

```text
棋盘行 0 = 图片最上方
纹理行 0 = 图片最下方
```

若棋盘使用从上到下的行号，则读取纹理时应使用：

```text
textureRow = rows - 1 - boardRow
```

否则最终完整图会在垂直方向上倒序。

### 6.4 拼图块身份

每块拼图至少包含以下逻辑信息：

| 数据 | 说明 |
| --- | --- |
| `PieceId` | 拼图块唯一编号，生成后不改变 |
| `TargetSlotIndex` | 正确目标格子编号 |
| `CurrentSlotIndex` | 当前所在格子编号 |
| `Row` / `Column` | 原图中的目标行列 |
| `Sprite` | 当前块引用的运行时 Sprite |

完成判定只比较逻辑编号，不通过 Transform 坐标或画面像素判断。

## 7. 棋盘布局

### 7.1 棋盘区域

拼图棋盘应有一个明确的矩形区域，例如 `PuzzleBoard`。其职责是定义：

- 棋盘中心位置；
- 最大可用宽度和高度；
- 拼图块父节点；
- 拼图层级与边界；
- 原图宽高比适配。

棋盘必须保持原图宽高比。适配规则为：

1. 先尝试铺满棋盘最大宽度。
2. 如果计算后的高度超过可用高度，则改为铺满最大高度。
3. 另一方向居中留空。
4. 不拉伸原图，不分别设置不同的 X、Y 缩放比例。

### 7.2 格子位置

格子按从左到右、从上到下编号：

```text
slotIndex = row × columns + column
```

每个格子的中心位置由棋盘矩形和行列数计算，不依赖场景中预先摆放大量空对象。

对于不能整除的原图像素，Sprite 像素尺寸可能相差一个像素，但屏幕上的棋盘格仍应无缝覆盖完整棋盘。后续视觉验证要重点检查高分辨率下是否出现细线、闪烁或块间缝隙。

### 7.3 完整原图的用途

场景中的 `nanoka_image1` 完整图建议只承担以下一种或两种用途：

- 难度选择阶段的预览图；
- 游戏中可选的低透明度底图提示。

第一版默认在游戏开始后隐藏完整图，避免直接透过拼图看到答案。若后续增加提示功能，应由明确按钮临时显示，并且不影响拼图逻辑状态。

## 8. 打乱规则

使用等概率随机排列打乱所有 `PieceId`。

要求：

- 打乱结果不得与完成排列完全相同。
- 至少应有两个拼图块不在正确位置。
- 打乱只改变拼图块与格子的映射，不改变拼图块身份和目标编号。
- 第一版允许任意两块交换，因此所有排列都可以恢复，不需要处理滑块拼图的奇偶可达性。
- 重开时重新生成随机排列，不要求复用上一局顺序。
- 调试和自动化测试时应允许注入固定随机种子，以便复现问题；正式游戏使用正常随机种子。

不建议使用“随机交换若干次”代替完整洗牌，因为该方式分布不均且难以保证不同难度的打乱质量。

## 9. 输入与交换反馈

### 9.1 有效输入

以下条件全部满足时才能开始拖动：

- 游戏状态为进行中；
- 当前没有交换动画；
- 指针命中有效拼图块；
- 完成面板和难度选择面板均未遮挡棋盘；
- 当前拼图块未被其他指针占用。

### 9.2 拖动表现

建议表现：

- 被拖动块轻微放大或提高亮度；
- 被拖动块临时提高 Sorting Order；
- 原格子显示半透明占位；
- 当前可交换目标显示描边或高亮；
- 拖动位置限制在合理屏幕范围内，但不强行改变逻辑格子。

### 9.3 松开结果

| 松开位置 | 结果 | 是否计步 |
| --- | --- | --- |
| 另一有效拼图块 | 两块交换 | 是 |
| 当前块自己的格子 | 返回原位 | 否 |
| 棋盘空白边缘 | 返回原位 | 否 |
| 棋盘外 | 返回原位 | 否 |
| UI 按钮或面板 | UI 优先处理，拼图返回原位 | 否 |

交换应先更新并验证逻辑状态，再播放表现动画。动画被禁用或中断时，也必须将两个拼图块校正到逻辑格子的精确位置。

## 10. 游戏状态

第一版只需要以下状态：

| 状态 | 说明 | 是否接收拼图输入 |
| --- | --- | --- |
| `SelectingDifficulty` | 等待玩家选择切分程度 | 否 |
| `Preparing` | 创建拼图块并打乱 | 否 |
| `Playing` | 正常计时与交换 | 是 |
| `Swapping` | 两块正在交换动画 | 否 |
| `Completed` | 已完成并显示结算 | 否 |

状态切换应集中维护，避免难度面板、拼图块和完成面板分别保存互相冲突的“是否正在游戏”布尔值。

## 12. 按钮行为

### 12.1 退出按钮

`Btn_Exit`：

- 游戏中点击后返回标题场景。
- 如未来需要防误触，可增加简单确认框；第一版可直接返回。
- 离开场景前停止计时、交换动画和运行时拼图对象的输入。

### 12.2 重开按钮

`Btn_Restart`：

- 保留当前难度。
- 取消当前拖动和交换动画。
- 清理当前运行时拼图块。
- 使用相同切分程度重新生成并打乱。
- 时间和步数归零。
- 完成面板关闭。

### 12.3 返回难度选择

第一版建议在难度面板关闭后，通过一个独立的“难度”按钮或重开确认面板进入难度选择。若暂时不增加该按钮，则玩家可以返回标题后重新进入场景选择难度。

为保持第一版范围简单，默认验收不强制增加游戏中的“更换难度”按钮。

## 13. 计时与步数

计时规则：

- 玩家确认难度后，在拼图生成和打乱完成时开始。
- `SelectingDifficulty`、`Preparing` 和开场动画期间不计时。
- 交换动画期间继续计时。
- 完成判定成立时立即停止。
- 显示格式最低为 `mm:ss`；超过 59 分钟时允许显示 `hh:mm:ss`。
- 使用不受暂停菜单动画影响的时间来源时，应在实现中明确；第一版没有暂停功能。

步数规则：

- 一次有效的两块交换记为一步。
- 无效拖动、拖回原位和松开到棋盘外不计步。
- 动画未结束时的额外输入被忽略，不计步。
- 重开后归零。

第一版不保存历史最佳时间和最佳步数，避免引入额外存档范围。

## 14. 音效与动画

可复用项目现有音频和 DOTween，但不是核心规则的前置条件。

建议音效节点：

- 点击普通按钮：通用选择音效；
- 有效交换完成：轻量拼图放置音效；
- 无效松开：轻量取消音效，可选；
- 游戏完成：完成提示音效。

建议动画：

- 拼图块选中时轻微缩放；
- 两块交换时使用短距离平滑移动；
- 完成时拼图块轻微统一闪亮或淡出缝隙；
- 完成面板淡入。

生命周期要求：

- 重开、退出、对象禁用或销毁时必须终止相关 Tween。
- Tween 被终止后要把拼图块校正到逻辑位置。
- 交换动画期间禁止重复输入，避免拼图块重叠或状态不同步。

## 15. 后续代码职责建议

后续第一方代码统一使用传统大括号命名空间：

```text
NanokaGame.Games.Jigsaw
NanokaGame.Games.Jigsaw.UI
```

建议保持少量明确组件，不引入 Manager、事件总线或依赖注入框架。

可采用以下最小职责划分：

| 类型职责 | 说明 |
| --- | --- |
| 棋盘状态 | 普通 C# 类，保存拼图排列、交换和完成判断，不依赖 MonoBehaviour |
| 游戏控制器 | 负责状态切换、创建本局、重开、计时和完成流程 |
| 拼图块视图 | 负责指针输入、拖动显示和把操作请求交给控制器 |
| UI 控制器 | 负责难度选择、HUD、完成面板和按钮转发 |

不应由拼图块视图直接修改其他拼图块的逻辑编号，也不应仅根据 Transform 位置判断是否完成。

## 16. 异常与边界情况

后续实现必须处理：

- 原图引用缺失：阻止开始并在 Console 输出包含对象上下文的错误。
- 行数或列数小于 1：拒绝创建本局。
- 行列数导致块数量超过安全上限：拒绝开始；第一版固定难度不会触发。
- 原图尺寸不能整除行列数：按比例边界算法覆盖全部像素。
- 打乱结果仍是完成状态：重新打乱。
- 玩家在拖动时点击重开或退出：取消拖动并恢复/销毁临时状态。
- 交换动画中对象被禁用：停止动画并同步到逻辑位置。
- 完成瞬间重复松开：完成状态只能结算一次。
- 不同分辨率下棋盘越界：按保持宽高比的规则重新适配。
- Sprite 过滤产生细缝：检查边界计算、位置精度、相机像素对齐和材质采样，不通过随意扩大碰撞范围掩盖视觉问题。

## 17. 测试与验收标准

### 17.1 纯逻辑 EditMode 测试

后续至少覆盖：

- 创建 `4×2`、`6×3`、`8×4` 棋盘时块数量正确。
- 每个目标格子编号唯一且连续。
- 不可整除尺寸的切片边界完整覆盖原图且不重叠。
- 棋盘行与纹理行转换后图片方向正确。
- 交换两块后两个 `CurrentSlotIndex` 同步更新。
- 交换同一格不增加步数。
- 打乱结果不是完成状态。
- 任意交换后完成判定结果正确。
- 最后一步完成时只触发一次完成结果。
- 使用固定随机种子时排列可复现。

测试命名示例：

```text
CreateSlices_WhenTextureSizeIsNotDivisible_CoversEveryPixelExactlyOnce
Shuffle_WhenPermutationMatchesSolvedState_ProducesAnotherPermutation
SwapPieces_WhenDifferentSlotsAreSelected_UpdatesBothSlotIndices
IsCompleted_WhenEveryPieceMatchesTargetSlot_ReturnsTrue
```

### 17.2 PlayMode 测试

后续至少覆盖：

- 选择不同难度后生成正确数量的拼图块。
- 游戏开始前不计时、不接收拼图输入。
- 有效拖放交换两块并增加一步。
- 无效拖放返回原位且不增加步数。
- 交换动画期间第二次输入被忽略。
- 重开后时间、步数和拼图排列被重置。
- 完成后停止计时、锁定输入并显示完成面板。
- 完成面板重开按钮使用当前难度开始新一局。
- 退出按钮返回标题场景。

### 17.3 视觉验收

必须在 Game View 检查：

- 三档难度均能完整还原原图。
- 拼图没有上下颠倒、左右镜像或行列错序。
- 相邻拼图之间没有明显透明缝隙或纹理串色。
- 拖动中的拼图位于其他拼图上方。
- 交换动画结束后位置完全对齐。
- 难度面板与完成面板能正确阻挡棋盘点击。
- 文字不溢出，按钮可点击。
- 常见分辨率与宽高比下棋盘不和 HUD 重叠。
- 场景中没有 `Missing Script`，EventSystem 不缺失也不重复。

## 18. 第一版完成定义

第一版拼图玩法完成时应满足：

- 玩家可以在进入场景后选择简单、普通或困难。
- 游戏按选择的行列数在运行时切分 `nanoka_image1`。
- 切图不修改原始图片资源，不要求开启 Read/Write。
- 所有拼图块被有效打乱，且初始状态不是完成状态。
- 玩家可以通过拖动一块到另一块来交换位置。
- 无效拖动不会改变逻辑状态或步数。
- 动画期间不会发生重复交换或状态不同步。
- 时间和步数显示正确。
- 拼图完成后能正确结算并显示完成面板。
- 重开和返回标题功能正常。
- Unity 编译无新增错误或警告，相关测试通过，Game View 视觉验收通过。

## 19. 第一版范围外

以下内容不在本次玩法范围内：

- 自定义导入玩家本地图片；
- 多张图片图库与联网下载；
- 拼图块旋转；
- 不规则齿形拼图；
- 自由散落式拼图桌面；
- 提示次数、道具、体力或广告；
- 排行榜、账号、云存档；
- 每日挑战；
- 复杂最佳成绩与成就系统；
- 关卡编辑器。

如后续需要扩展，应在不破坏当前“切分、排列、交换、完成判断”核心逻辑的前提下单独设计。
